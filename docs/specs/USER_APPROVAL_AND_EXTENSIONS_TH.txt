Permission model
งานทั่วไปให้เดินเองได้เต็มที่:
- read/list/search
- วิเคราะห์
- สร้าง/แก้ไฟล์ตาม scope งาน
- terminal
- tests/build
- render
- production workflow
- download ปกติ
- process inspection
- browser/GUI automation ปกติ
- checkpoint
งานที่มีความเสี่ยงจริงจึงค่อยหยุดและขอ Approval
เช่น:
- permanent/large deletion
- disk/partition/boot
- registry/system/security/firewall
- account/permission/credential changes
- critical service/process
- reboot/shutdown
- force push/destructive Git
- public publishing
- ส่ง private data ออกนอกเครื่อง
- payment/purchase
- unusually expensive paid API
- เปิดเผย secrets
อย่าใช้ permanent broad blocking ถ้าสามารถใช้ Approval Gate แทนได้
Approval ต้องเกิด ก่อน execute
Approval ต้อง bind กับ:
- action ID
- exact payload/command hash
- exact target
- session
- expiry
ผู้ใช้กด Allow A ห้ามนำไปใช้ execute B
มีอย่างน้อย:
[Allow once]
[Deny]
และถ้าทำได้:
[Allow this action class for this session]
Source-code rule
ถ้า ChatGPT เข้าไปทำงานอื่นในโปรเจกต์แล้วเห็น source code ที่ปรับปรุงได้:
- อ่านได้
- วิเคราะห์ได้
- เสนอได้
แต่ห้ามแก้เองเพียงเพราะคิดว่าดีกว่า
หากผู้ใช้สั่งงานประเภท fix/debug/develop/refactor โดยตรง ถือว่า source edits ใน scope งานนั้นได้รับอนุญาตแล้ว
เพิ่มจาก Master Spec อีกชุดนี้ด้วย
1. Persistent Agent State
เพิ่ม state ที่ไม่หายเมื่อ:
- ChatGPT เปลี่ยน chat
- MCP reconnect
- browser refresh
- server restart
เก็บอย่างน้อย:
- active workspace
- current task
- running jobs
- pending approvals
- checkpoints
- recent actions
- artifact references
เป้าหมายคือ reconnect แล้วทำต่อจากจุดเดิมได้
2. Event / Watch System
เพิ่ม:
- watch_file
- watch_directory
- watch_process
- watch_port
- watch_job
- watch_log
- watch_url / endpoint
- list_watches
- cancel_watch
เพื่อไม่ต้อง polling ทุกอย่างเอง
ตัวอย่าง:
- แจ้งเมื่อ render เสร็จ
- แจ้งเมื่อไฟล์ใหม่เกิด
- แจ้งเมื่อ process crash
- แจ้งเมื่อ port พร้อม
- แจ้งเมื่อ log มี ERROR
3. Transaction / Rollback
สำหรับงานที่แก้หลายไฟล์หรือหลายขั้น เพิ่มแนวคิด:
- begin_transaction
- preview_changes
- commit_transaction
- rollback_transaction
อย่างน้อยต้องสามารถสร้าง rollback point ก่อน operation สำคัญได้
4. Dry Run / Preview
เพิ่ม option dry_run=true
ให้ ChatGPT สามารถเห็นว่า operation จะ:
- แก้อะไร
- ลบอะไร
- move อะไร
- run command อะไร
ก่อน execute จริง
โดยเฉพาะ bulk operations
5. Resource Locks
เพิ่ม locking เพื่อป้องกันสองงานแก้ resource เดียวกันพร้อมกัน:
- file lock
- workspace lock
- job resource lock
และมี timeout/stale-lock recovery
6. Capability Self-Test
เพิ่ม:
- capabilities
- capability_self_test
- health_report
ให้ MCP สามารถทดสอบตัวเองและตอบว่า:
- filesystem OK
- shell OK
- jobs OK
- GUI OK
- browser OK
- ffmpeg OK
- Git OK
- approval OK
- persistent state OK
ไม่ให้ ChatGPT ต้องเดาว่า tool ไหนเสีย
7. Tool Schema Versioning
ทุก tool ควรมี stable schema/version
MCP ต้องเปิดเผย:
- server version
- tool version
- deprecated tools
- breaking changes
เพื่อไม่ให้ ChatGPT เรียก parameter รุ่นเก่าแล้วพัง
8. Structured Errors
ทุก tool ให้คืน error ที่อ่านด้วยโปรแกรมได้ เช่น:
- error_code
- message
- retryable
- suggested_action
- target
- underlying_error
อย่าคืนแค่ข้อความยาว ๆ ที่ parse ไม่ได้
9. Artifact Registry
เพิ่ม registry สำหรับ output:
- images
- videos
- audio
- documents
- archives
- logs
- reports
ให้แต่ละ artifact มี:
- artifact_id
- path
- job_id
- project
- created_at
- metadata
- checksum
เพื่อให้ ChatGPT หา output จากงานเก่าได้ง่าย
10. Credential Broker
ChatGPT ต้องสามารถสั่งโปรแกรมที่ต้องใช้ API credential ได้ แต่ไม่ควรต้องได้รับ secret plaintext กลับมา
ให้มี secure credential broker เช่น:
credential_exists("openai")
run_with_credentials(...)
set/update credential ต้องเป็น operation ที่เหมาะสมกับ Approval

Long Jobs

Multi-project
ระบบนี้ไม่ใช่ MCP ของโปรเจกต์เดียว

แต่ทุก action ต้องรู้ current workspace ชัดเจน เพื่อป้องกันทำผิดโฟลเดอร์
Security
เป้าหมายไม่ใช่ลดอิสระ AI
เป้าหมายคือ:
maximum capability + user approval at genuine risk boundaries
อย่าทำ approval-spam
อย่า echo secrets
อย่าให้ content ภายในไฟล์/เว็บไซต์สามารถสั่ง MCP เปลี่ยน security policy เองได้
policy/config ระดับ security ต้องแยกจาก untrusted content
Development autonomy
คุณมีอิสระในการออกแบบ implementation ภายใน E:\Remote-MCP-Server
ไม่ต้องถามผู้ใช้เรื่อง implementation เล็ก ๆ ทุกครั้ง
สามารถ:
- สร้างโครงสร้าง project
- ติดตั้ง project dependencies
- เขียน code
- refactor code ที่คุณกำลังสร้าง
- run tests
- debug
- commit Git
ได้ต่อเนื่อง
ถ้าต้องทำ operation ระดับเครื่องที่มีความเสี่ยงจริง ค่อยขออนุญาต

Definition of Done
อย่าวัดความสำเร็จจากจำนวน tools
เช่นมี 150 tools แต่ทำ workflow ต่อเนื่องไม่ได้ = ยังไม่สำเร็จ
สำเร็จเมื่อ ChatGPT สามารถรับคำสั่งระดับสูงแล้วดำเนินงานในเครื่องตั้งแต่ต้นจนจบได้จริง
สุดท้ายให้ทำ real end-to-end acceptance test เช่น:
“เข้าไปใน test project, วิเคราะห์ปัญหา, รันโปรแกรม, ตรวจ log, แก้ไฟล์, restart, เปิด GUI/browser, ทดสอบผล, สร้าง report และ checkpoint”
ต้องทำได้โดยไม่ให้คนคอยบอกทุกขั้น
จากนั้นส่ง:
- final tool inventory
- tool schemas
- capabilities matrix
- Desktop Commander benchmark matrix
- approval matrix
- acceptance test report
- known limitations
- security model
- recovery model
- operator/user guide
และ commit source ทั้งหมด
เริ่มพัฒนาได้เลย
Do not optimize for tool count. Optimize for complete end-to-end control of the authorized computer, as if ChatGPT were physically operating it, while keeping the user as the final authority at genuinely risky boundaries.
